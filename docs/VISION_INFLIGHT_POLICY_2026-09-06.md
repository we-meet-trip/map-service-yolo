# Vision in-flight policy boundary

Work started 2026-09-06; follow-up on 2026-09-07 to R3 `7ad04f95d3e2763a0bb1e0898ad2fe1534f8b9f6`. The socket already checked its JWT/owner/service policy at handshake and spent one account quota unit before each inference. It now checks the User BFF again after `_process` completes, before sending the generated body, using `consume=false` and the original owner. A DOB correction, required policy revision, expired/revoked session or unavailable permission service withholds that result and closes with the existing bounded error contract. No second quota unit is spent, including a user's last allowed inference.

`AGE_INFORMATION_REQUIRED` is propagated only as an allowlisted 403 code alongside `AGE_RESTRICTED` and `SERVICE_POLICY_REQUIRED`; provider error messages are never reflected. A 503 becomes the generic unavailable message / close 1013 without the original content. A rejected handshake still remains unaccepted; Client rechecks consent state. No DOB is added to Vision or provider payloads. User must supply its fresh server eligibility checks and Client must retain its pending-result discard on locally revoked optional AI consent. There is no durable per-feature AI-revocation endpoint in the current server contract, and an already-sent provider request cannot be recalled.

Regression uses coroutine events to change permission while inference is pending for both text and image. It checks missing DOB/minor/stale policy/session/503 denial, no protected sentinel fields, runtime release and exactly one consumed permit. Separate owner tests preserve accepted same-owner int/string behavior, reject changed owners, and an actual PermitClient with HTTP mock transport proves `[false,true,false]` request bodies and zero remaining quota success. Existing reconnect, quota, malformed inputs, runtime imports and full tests must pass on the candidate CI SHA; no real model/provider calls are needed.
